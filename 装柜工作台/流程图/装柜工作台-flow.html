装柜工作台 · 端到端业务流程

供应链协同平台 · 装柜计划模块 M01｜从数据准备判断到生成 / 保护式重新预排的入口闭环

1进入工作台：SCM 每日首屏入口，默认载入当前需求月份
2选择需求月份：默认当前月（N～N+6，一期仅支持单月），汇总预测版本、批次池与货柜计划
3查看数据准备状态：需求版本、排程批次、QC、SAP 四类数据的最近同步时间与异常
具备可进入预排环节
每项状态右侧提供跳转入口
需求版本 → 需求预测
排程批次 → 批次池
QC / SAP → 预警中心
分支数据准备校验：是否存在缺失或异常？
缺失保留预警条目，提示预测负责人 / 数据责任人处理
缺少启用预测版本 → 不自动阻断既有计划
主数据缺失 / QC 风险 / 批次不足 → 保留预警，不静默排除
4查看三张核心指标卡：装柜覆盖（已排 SKU 数 / 有需求 SKU 数）｜本周期待办（全量预警数）｜CBM 风险（超限 + 低装载）；点击可跳转对应明细
5处理 SCM 待处理清单：按 当日执行风险 > CBM 超限 > QC/批次不足 > SAP 差异 > T0 延期 > 数据缺失 排序，逐条「去处理」
首次点「生成预排」：按 SKU + 客户 + 目的地的需求缺口生成货柜建议
仅使用可排且 QC 可满足的批次
CBM 风险卡可跳预警中心并筛 CBM 两类
分支是否已有计划？
已有点「重新预排」→ 二次确认后执行保护式重新预排
既有货柜不被改写
仅补新增需求或已有缺口；需求下降形成计划余量预警
6跳转与留痕：清单与指标卡联动刷新；处理动作写入操作日志；缺口消除后对应条目自动移出清单
铁律：工作台是判断层，不是处理层。它只回答「能不能排柜、先处理什么、点进去到哪儿处理」；实际的数量、批次与货柜调整一律在排程视图、批次池等对应模块完成，本页不提供计划内容编辑入口。
