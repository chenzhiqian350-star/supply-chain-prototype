# 沟通记录 · 装柜计划执行表

## 需求确认（已确认决策）
- 定位为**仓库按日执行的执行层**，替代线下 Excel 计划表；计划数据一律只读，工厂执行层只补录实际信息。
- **已取消货柜不在执行表展示**（提升为需求目标第 3 条）：避免仓库按已作废计划执行；页面常驻标签「已取消货柜不可见」。
- **14 列**：货柜编号、客户、目的地、运输方式、计划时段、SKU 批次数、箱数、CBM、QC 摘要、预计 T0、柜号、封条号、状态、计划有更新；表头固定、横向滚动。
- **字段可编辑性**：仓库仅维护柜号与封条号；SKU、批次、数量、计划日期一律只读，不提供编辑入口。柜号 SCM / SCM 主管 / 仓库可补录（发运后仍可）；封条号仓库为主责。
- **「计划有更新」时效**：24 小时内高亮、之后转灰、**永久保留**；悬浮查看该货柜全量更新时间列表。
- **风险只提示不阻断**：执行日后仍未匹配 SAP 出库 → 显示「SAP 对账差异」预警；CBM 超限进入执行 → 显示高优先级对账风险；处理在预警中心完成。
- **导出与打印**：随时在线预览、下载、打印，不依赖人工确认动作；CSV 文件名「装柜计划执行表-YYYYMMDD.csv」（14 列中文表头，带 BOM）。
- **边界**：本 PRD 只描述执行表本身（筛选、列、补录、导出、对账）；货柜计划内容的编辑、状态机与权限矩阵已在《排程视图》PRD V1.1 覆盖，本文只做交叉提及，不重复展开。

## V1.2 补充确认（2026-09-21）
- **移除「SKU/批次数」与「QC 摘要」两列**：仓库执行不依赖这两列信息，移除以收窄表格、减少横向滚动；执行表由 **14 列精简为 12 列**（货柜编号、客户、目的地、运输方式、计划时段、箱数、CBM、预计 T0、柜号、封条号、状态、计划有更新）。
- **「CBM」列增加单柜上限对比**：展示为「当前装载量 / 单柜上限（利用率）」，例如 `51.80 / 53.00 (97.7%)`；单柜上限取该柜型容量（40'RF=53 / 40'HQ=63 / 20'RF=21 / 20'GP=23，随主数据调整），与排程视图 CBM 利用率口径一致；**超过上限整格标红、利用率不高于 85% 标黄**。
- **列宽重新标定**：表头统一不换行，列宽按 12 列布局重新分配（CBM 列加宽以容纳「装载量 / 上限（利用率）」）。
- **CSV 导出同步**：表头改为 12 列，CBM 列以「装载量 / 上限 (利用率)」文本导出。
- **「全部日期」筛选项修复（实现缺陷，同轮回归时发现）**：`renderExecutionBoard` 原用 `previous === ""` 判断「用户未显式选择」，而「全部日期」这份选项的 value 同样是 `""`，导致用户选中后立刻被默认逻辑顶回当天，该选项**实际不可用**。现引入 `executionBoardDateInited` 区分「首次进入」与「用户显式选择」，选中「全部日期」可保持并展示全部在排柜货柜（实测 156 行）。
- **列宽改为自适应**：原按**旧 14 列**用 `nth-child` 写死的列宽在删列后索引错位（表头「目的地 / 运输方式」折行），改为表头不换行 + 关键列 `min-width` + 水平内边距收紧至 6px，12 列在 1440 视口内不再横向滚动。
