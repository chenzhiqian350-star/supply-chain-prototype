# 沟通记录 · 排程视图

## 需求确认（已确认决策）
- 排程视图为 SCM 计划员「把货柜排到日期与时段」的核心工作台，提供 **月 / 周 / 日** 三视图。
- 三视图定位：日视图处理执行与 QC 风险，周视图核对排柜顺序，月视图跨周拖动改期；默认进入日视图。
- **每日装柜上限**由装柜日程主数据配置，默认 5 柜，修改后对后续排程生效。
- 所有排程调整统一进入**未保存状态**，支持撤销与批量保存；保存时校验每日上限、CBM、QC 完成时间与工作日规则。
- 日期链按「最晚 QC → 装柜 → ETD → ETA → T0」顺推：检验与装柜按**香港工作天**、离港与运输按**自然日**、T0 按**内地工作天**；PV/CV 特殊批次默认 +3 工作日；香港公众假期纳入香港工作日判断。

## V1.1 补充确认（编辑层，已确认决策）
- **产物形态**：在现有排程视图 PRD 上增补（一个模块一份 PRD），不拆分独立的货柜编辑页 PRD。
- **当日编辑**：编辑入口收敛在日视图（点击时段卡片 → 货柜编辑抽屉）与月/周视图（拖拽改期）两条路径，月/周视图不提供货柜内容编辑。
- **货柜详情抽屉**：五区域结构（状态栏 / SKU 明细 / 货柜与执行信息 / 货柜时间轴 / 操作日志）；14 列 SKU 明细、14 个执行信息字段、12 个操作按钮的触发条件与权限全部入 PRD。
- **上下架**：批次池按「同目的地优先 + 同 SKU 优先」排序；不同客户、不同目的地同柜**硬阻断**（提示文案原文入 PRD）；下架 / 替换 / 取消货柜后批次状态一律回「可排」回池。
- **数量不可直改**：装柜数量不能直接输入，只能通过上架、拆批、替换、下架四条路径改变。
- **拆批**：仅可排批次、整箱为最小单位、CBM 超限时给最少整箱移出建议、拆出记录沿用原 SAP 批号（拆分序号追溯）。
- **明细预览与下载**：26 列实时预览；《装柜执行表》Excel 下载（14 列中文表头），无 Excel 组件时降级 CSV。
- **状态机**：计划中 → 执行中（装柜日闸门）→ 已完成（SAP 出库覆盖）/ 已取消；装柜日后变更需 SCM 主管授权（必填原因）；TT 字母/序号仅发运后 SCM 可补录。
- **截图**：抽屉、批次池、拆批、明细预览四张专项截图由现有系统实截（临时驱动页调起抽屉/弹窗，截完即删，未改动现有系统）。
- 右栏活原型新增「批次池（#batches）」页面，作为上下架批次来源的对照视图。

## V1.5 补充确认（2026-09-21）
- **月视图日期格内改为按 5 个装柜时段分行**：每个工作日的日期格固定渲染 5 行（09:00-10:30 / 10:30-12:00 / 13:00-14:30 / 14:30-16:00 / 16:00-17:30），行首为时段短标签（悬浮显示完整区间），货柜卡片落在所属时段行，空格行以虚线占位并作为拖放目标；**日内直接上下拖动卡片即可改时段**，无需再切到周视图。周末格仍显示「周末不排柜」。

- **实现缺陷修复（同轮回归时发现）**：三视图渲染顺序为「月 → 周 → 日」，而 `bindDrag()` 原先只在 `renderMonth()` / `renderWeek()` 中调用，日视图 DOM 最后重建后未再绑定事件，导致日视图卡片与 5 个时段容器**实际不可拖拽**（需求与本文表述无误，属原型实现漏绑定）。现 `renderDay()` 末尾补调 `bindDrag()`，并给 `bindDrag()` 增加 `data-dragBound` / `data-dropBound` 幂等标记，避免三视图重复绑定。修复后已用真实 `dragstart` → `drop` 端到端验证：两柜互换成功并弹出提示。
